\section{Formal Evaluation Protocol}
\label{app:protocol}

The executable protocol is:

\begin{enumerate}
    \item Verify every configured dataset path with
    \texttt{experiments/run\_downstream.sh --check\_only --all}.
    \item Smoke-test the current code using a CPU, random-initialized one-batch
    forward pass.
    \item During recipe search, set \texttt{test\_each\_epoch=false} and
    \texttt{run\_final\_test=false}.  Rank candidates by mean best validation
    metric across two search seeds.
    \item Freeze the winning recipe before the formal runs.
    \item Train every formal dataset with the seed set recorded in its YAML
    configuration (the current EfficientNet-B0 recipes use seeds 42--46),
    always with \texttt{test\_each\_epoch=false}. Save the best validation
    checkpoint.
    \item Restore that checkpoint and evaluate the test set exactly once.
    \item Aggregate the final test values as mean and population standard
    deviation over the recipe's seed set. Do not choose a seed or epoch using
    test performance.
\end{enumerate}

All downstream training is launched through
\texttt{bash experiments/run\_downstream.sh}; direct invocation of the legacy
entrypoint can silently change path resolution.

\section{Data and Code Reproducibility Statement}

The codebase records exact dataset paths, input shapes, preprocessing, seeds,
training arguments, logs, and validation-selected checkpoints.  Public data
licenses and access conditions differ by benchmark; no dataset is redistributed
with the paper.  The CHB-MIT manifest follows the subject split of the
\cbramod{} benchmark code (CHB01--20/CHB21--22/CHB23--24 for
train/validation/test) \citep{wang2024cbramod}; the remaining manifests follow
the fixed subject- or trial-level partitions of the \cbramod{} and \reve{}
benchmark code \citep{wang2024cbramod,elouahidi2025reve}, with HMC using the
\reve{} partition \citep{elouahidi2025reve,alvarez2022hmc}.  Reproduction still
requires the documented dataset versions and local split manifests. We use
TUAB v3.0.1 and TUEV v2.0.1; for TUEV, the held-out test partition is the
official evaluation set and contains 29,421 segments in both v2.0.0 and
v2.0.1, while the newer release changes only the training and validation
counts (68,445/15,487 rather than 67,436/15,634).
